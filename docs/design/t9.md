# T9 九宫格（微信式键面 + 混合拼写引擎）

九宫格模式（issue #1/#2）：五列键面（左列候选条 + 3×3 字母组 + 右列功能列），
点按出通配候选，滑动/长按确认字母，交互对齐微信九宫格。视觉定稿以
`~/share/feelime/preview-t9/`（preview 页）+ 用户确认为准。

## 1. 引擎：混合拼写 schema（纯 algebra，零引擎改动）

- `luna_pinyin_t9.schema.yaml` 由 `scripts/generate-t9-schema.py` 从全拼
  schema 生成。核心是首/末字母保护规则 × 26 + 两条 xlit：

  ```yaml
  # 每个字母两条（a 示例）：末匹配 + 首匹配，级联产生「任意位置选字母」
  # 的全部组合——重复字母（nan 的 n26）只有首匹配规则能覆盖：
  - derive/^(.*)a(.*)$/$1A$2/
  - derive/^a(.*)$/A$1/
  # 大写字母保护完毕后，剩余小写字母 → 数字（通配）：
  - xlit/abcdefghijklmnopqrstuvwxyz/22233344455566677778889999/
  # 大写还原为小写（字母形态参与正常切分）：
  - xlit/ABCDEFGHIJKLMNOPQRSTUVWXYZ/abcdefghijklmnopqrstuvwxyz/
  ```

  生成器以 derive 级联模拟断言全部 424 音节的 2^k 投影覆盖，缺口音节
  自动补显式 derive（当前音节表零缺口）。只替换 speller 段（到
  `switches:` 为止）——切到 translator 会丢掉 zh_hans 默认简体开关。

- 每个音节由此拥有全部 2^k 种「确认字母/通配数字」混合拼写形态：
  `ni → n/4/ni/n4/4i/44/ni4/n4i/...`（424 音节 → 4,738 形态）。
  键面点按发数字、滑动发字母，librime 音节图原生完成切分与过滤，
  **键盘侧零过滤逻辑**。
- alphabet 为 `a-z2-9`；`1`/`0` 不进引擎（组合中是死输入，键面层一律
  commitText 旁路上屏）。
- prism 独立命名 `luna_pinyin_t9`（约 140KB，级联形态的体积代价；
  table/reverse 与全拼逐字节相同——音节 id 是词典级的，与 algebra 无关）。
- **构建坑**：yaml-cpp/deployer 对 algebra 列表项有 2 空格缩进要求（与
  `algebra:` 同级）；4 空格（合法 YAML）会让 rime_deployer 静默 exit=1。

## 2. 键面（keyboard.js `renderT9` + `.t9-*` CSS）

```
        c1(左列)      c2        c3        c4        c5(功能列)
r1-4    [常用字符/    @#.(1)    ABC(2)    DEF(3)    退格
音节条   音节条]      GHI(4)    JKL(5)    MNO(6)    重输
(竖拖)                PQRS(7)   TUV(8)    WXYZ(9)   emoji
        [符号]       123(2/3宽) mic(5/3宽) 中英(2/3) 确认/换行
```

- 左列 `.t9-side`（grid-row 1/5）：空闲 = 常用字符（中文标点，
  `T9_SIDE_CHARS`，与 `@#.` 键的西文/技术符号集互不重复）；组合中 =
  拼音音节候选（§3）。native pan-y 滚动，**不 bindTouch**（preventDefault
  杀拖动的既有教训），底部符号键 = 符号面板入口。
- 字母组键：主字形 = 字母组，右上角标 = 数字（与空格的 0 角标同款）；
  `data-key` 保留数字 1-9（mic=0）——`devtools_key_geometry` 与套件
  零改动。
- 底行：123 与中英切换各 2/3 键宽，省出的空间全给 mic/空格（5/3 宽）。
  中英键复用 `cnEnKey()`（大字形当前模式 + 右下角快捷对目标，长按模式
  菜单），不另造样式。
- 工具栏/候选条互斥继承生产 `#candidateBar` 行为（组合中按钮隐藏），
  T9 零改动。

## 3. 手势仲裁（setupFlick 内 `t9Flick` 路由）

| 手势 | 语义 | 通道 |
|---|---|---|
| 点按字母键 | 整组通配数字 | `Native.key(数字)` 进引擎 |
| 上滑 | 字面数字 | `sendSymbol`（commitText 旁路；进引擎会变候选选择器） |
| 下滑 | 中间字母确认拼写 | `sendText` 进引擎；**7/9 = 拆分浮层**（下左/下右继续滑选 q/r、x/y） |
| 左/右滑 | 首/尾字母确认拼写 | `sendText` 进引擎 |
| 长按 | 三行弹层（issue #9，3.38.0）：上行=字母组小写、中行=左符号·数字·右符号、下行=大写（5 → `jkl / 、5： / JKL`） | `openT9Popup({grid:true})`，字母（大小写原样）/符号 `literal` 直上屏（3.40.0 定稿：弹层选字母=直接打这个字母，不进组合），数字格=通配进引擎 |
| mic 上滑 | 字面 0（右上角标提示） | `sendSymbol` |
| mic 左右滑 | 光标 scrub（T9 唯一保留 scrub 的键） | 通用 scrub 分支（mic 挂 `data-key=0` 让选择器认领） |
| 确认键（组合中） | 提交高亮候选 | `choosePoolCandidate`，**拦截 `Native.enter`**（EnterRaw 会 ESC+把数字串原样上屏）；空闲=换行 |
| 重输 | 清空当前组合 | `clearComposing` |
| emoji | 直达数字板 emoji 视图 | `showNumpad()` + emojiView |
| 123 | 直达数字板 | `showNumpad()`（点按直达，区别于 qwerty 的长按） |
| `@#.`（1 键） | 候选条展开西文/技术符号行 `@#.*+-_/=` | `sendSymbol` 直上屏；引擎候选/联想/组合任一出现即让位 |

浮层提交（`closePopup` 的 `enginePath` 分支）：字母格（上行小写、下行
大写）与符号格都是 `literal` 直上屏（`sendSymbol`，大小写/字形原样落，
3.40.0 用户定稿：弹层选字母=直接打这个字母）；数字格 = 通配进引擎
（与点按同义，不拖直接松手不改变输入）。拼音里「确认字母」由下滑/横滑
手势承担：滑动走 `sendText` 进引擎，T9 通道一律归一小写（schema 的
alphabet 只收小写+数字，大写键会被 rime recognizer 的大写规则截成
英文原文段直出）。
三行弹层的选中语义（issue #9 定稿：**相对跟手**，
qwerty accent 弹层同款）：
开层默认高亮中行数字格（锚点）；高亮位置 = 锚点 + 手指位移（虚拟光标取
最近格）——手往左滑高亮往左（到左符号）、往下滑高亮往下，和手指位置是
**相对关系**，手指全程不必碰浮层。虚拟光标滑出卡片边界才淡出（scale
.92 / opacity .5）+ 浮层上方固定「松手撤销」toast（`showPopupCancelTip`，
不跟手），滑回卡片内自动恢复、松手不落字。按点 12px 内的微动不动高亮
（吃手指抖动，松手仍落数字格）；手感档（popupSnap）缩放死区与卡片
边界容差。每键的
两个符号在键面左上角小字展示（`.t9-hint`，`LAYOUTS.t9.keySymbols`），
长按能出什么不用猜。符号分配（输入过程中高频优先）：

| 键 | 左符号 | 右符号 | 键 | 左符号 | 右符号 |
|---|---|---|---|---|---|
| 2 | — | & | 6 | ； | ～ |
| 3 | （ | ） | 7 | 《 | 》 |
| 4 | 「 | 」 | 8 | … | · |
| 5 | 、 | ： | 9 | % | / |

## 4. 音节候选条与组合重写

- 数据：`scripts/generate-t9-syllables.py` 从 `luna_pinyin.table.txt` 的
  syllabary（424 音节）+ 正文词频行生成「数字串 → 音节」正向索引（组内按
  词典词频降序；词频含小数与科学计数——`了 le 1.49585e+06` 这类最高频
  行）+「音节 → 词频」权重表 + 「首数字 → 声母」前缀层，**内联进
  keyboard.js 生成标记块**（热更包/打包器/资产存储都是四文件硬编码，
  不新增资产文件）。
- 渲染：`renderT9Side`（updateComposing 尾部钩子，内容签名不变不重建以保
  滚动位置）。完整音节可点、声母前缀置灰仅提示。候选跨前缀长度按词频
  全局降序（`64` → ni 在 mi/o 前），声母前缀缀尾。
- 确认边界：键盘侧 `t9ConfirmedLen`（锚定确认前缀文本）只在点选音节时
  推进；引擎回显的段空格是切分猜测不是用户确认——`64426` 首字未确认时
  左列只出首字读法，不提前展示第二字的 ga/ha/gan/gao。退格删进未确认
  尾段边界保留，删进已确认段才从头重算；变体重放期间点选丢弃；边界
  跟随组合生命周期，不随键面重绘（横竖屏切换）清零。librime 连续造词
  把已选汉字写进 preedit（`你426`）：已选文字不进音节枚举（剥前缀非
  拼写字符），剩余段照常可点，点选重写保留汉字前缀。
- 点选音节：组合原子重写为「已确认字母 + 选中音节 + 剩余数字」
  （`64426` 点 `ni` → `ni426`），复用双拼变体的 `switchToVariant`
  （variantReplaying 冻结、目标回显检测、1500ms 安全阀；T9 下跳过
  expand 变体列高亮）。
- 候选条 chevron 展开层：左列改渲染同一份音节候选（`renderVariants` 的
  T9 分支），右侧仍是候选字词。
- preedit 读音：候选字上方显示读音重建（`t9Reading`）——按引擎段切分后
  段内贪婪最长覆盖（同长取词频高，`64426` → `ni'hao`、`94664` →
  `zhong`），剩余无匹配原样保留；`t9PreeditLabel`（字母/数字间插窄空格）
  仅作兜底。

## 5. 原生接线

- `InputMode.T9("t9")` → `EngineFactory` 建 `luna_pinyin_t9` 会话；
- `BridgeContract.isValidComposition` 增加 `allowDigits` 形参：仅 T9 模式
  放行 `'2'..'9'`（音节条重写的混合组合串），Direct/密码字段等通道照旧
  拒数字（JVM 单测 BridgeContractCapabilityTest）。
- 模糊音：不影响 T9（模糊 derive 在 pinyin 域，数字串不经模糊）。
- 联想：T9 上屏后同样出接续词。

## 6. 已知边界

- degrade（Direct 顶班）激活时 T9 字母语义由 qwerty 键面接管，恢复后
  回到 T9 键面（mode-fallback 通用路径，未特判）。
- 引擎候选为繁体的会话（用户关简体）中，混合串候选同样繁体——与全拼
  行为一致，非 T9 特有。
- 1/0 在组合中是死输入：空闲时经字面通道上屏（1 键点按 = 符号行 +
  工具栏收起（× 取消复原，无长按态）、上滑 = 字面 1；mic 上滑 = 字面 0），
  不进引擎。
- 空格键：右上角 `0` 角标提示上滑字面 0，长按圆点挪左上（`.t9-space`）；
  点按 = 空格/提交高亮候选，横滑 = 光标 scrub。
- 1 键符号行的 chrome 态（工具栏收起 + × 取消）由 `t9BarChrome` 守护：
  空闲引擎事件/原生状态刷新不得翻回工具栏；联想词到达才让位复原。
